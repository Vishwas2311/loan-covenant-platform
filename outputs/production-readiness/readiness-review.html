Production-readiness review · 5 November 2026

Covenexa: Core, DPS and UI on the local real stack

Keycloak, SQL Server 2022, Azure OpenAI, WireMock bank stubs, one 8-CPU host. No product code was changed during the review.

NOT READY

One critical requirement fails (covenant direction in extraction), and three high-severity failures appear at a real bank's size. The fixes are contained and planned; a second review follows phase 1.

Why not ready

  1. Wrong covenant direction (Critical). "The DSCR shall not be less than 1.35" is extracted as DSCR < 1.35. A floor becomes a ceiling, so compliant borrowers show as breached and the reverse. The citation check passes and confidence is 0.85; only the RM's review catches it.
  2. Bank-wide pages fail above 2,100 CPs (High). With 2,225 CPs, admin and auditor get HTTP 500 on portfolio, CP list, tasks and the breach report: SQL Server's 2,100-parameter limit.
  3. Capacity with real portfolios (High). One RM with 60 CPs waits 4–6 s for the breach report; 25 such RMs at once exhaust the database pool (10–58% errors, 66 s time-outs).
  4. Uploads deadlock on SQL Server (High). 22–70% of concurrent uploads fail with deadlock 1205 on the production database. DPS sends NVARCHAR strings to VARCHAR columns. The local stack's SQLite hid it.

  • Authentication, role gates and CP isolation hold in Core and DPS.
  • Ask AI stays in the RM's portfolio, cites records, refuses other RMs' CPs.
  • A planted instruction did not change extracted thresholds.
  • Restore is byte-identical; nightly run, e-mail hand-off and two-node Quartz work.

Path to "ready with conditions"

  1. Fix the operator wording and add an operator-sanity check; credit analysts label at least 20 agreements and 20 statements.
  2. Batch every id list in 500s; bank-wide reads without an id list.
  3. Remove the N+1 lookups and table scans on portfolio pages; cache library data.
  4. Match DPS bind types to the columns; retry deadlocks; test DPS on SQL Server in CI.
  5. Write the CP cache whenever covenants are applied.
  6. Repeat the real-portfolio, bank-wide and upload load tests, then review again.
