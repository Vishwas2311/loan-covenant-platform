Rebuilt and extended, with some feature gaps.

One evidence-backed table compares covenanttrackingphase1.2, covenant-monitoring and the combined Covenexa platform. This review changes none of the three projects.

Yes. The combined application is built on both earlier projects, with different kinds of reuse: the old Java monitoring backend was forked into Core, while the Python document-reading capabilities were ported and rebuilt into DPS. The React UI was rebuilt.

Source-byte comparison: all 396 old monitoring backend production-source/resource files have matching paths in new Core: 301 are byte-identical, 95 changed, none missing. All 123 old backend test files remain: 91 identical, 32 changed. These are files, not counts of Java classes. Old frontend/src has 123 files: zero byte-identical files at the same relative paths, five matching paths changed and 118 without same-path counterparts. The 15 old Python modules and 32 DPS source modules have no byte-identical nonempty whole-module matches; the new extractor explicitly identifies itself as a port. This establishes ancestry, not blanket behavioral equivalence.

The combined app is not a complete UI superset. Advanced eligibility, key-value/obligor table controls, source-code measure mapping, parts of onboarding, the standalone formula builder and the old calendar interface are reduced or absent from the replacement UI even where Core retains the capability. The most concrete static regression risk is DataSources.tsx:94–104: editing an existing table initializes COLUMNAR / CP_ID and blank code/value columns, so saving can change an old key-value/obligor mapping. This was not reproduced against a live database.

The supplied architecture broadly matches the service split and real Flow A/Flow B implementations, but needs qualifications: Flow B derives inputs, not covenant ratios; base local Compose uses SQLite for DPS although SQL Server is supported; DPS originals use a local content-addressed file store; statement parsing normalizes to INR crore and does not automatically extract all period columns. Local WireMock, mock ML, Keycloak and optional Mailpit are substitutes/configurations, not evidence of production bank, ML, Entra or mail connectivity.

Not-carried legacy features found in this review include financial news/RSS, chat-generated chart payloads, the entity-type pie and a live industry-risk treemap. An unused chart component does not prove a shipped feature. The earlier optional-news decision is not implementation evidence.
